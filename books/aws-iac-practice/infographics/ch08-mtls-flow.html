証明書はKMSで署名し、APIは2段階でクライアントを確かめる
秘密鍵はKMSとクライアントの手元から出さない。失効はAPI Gatewayが見ないので、オーソライザーが台帳で補います
発行証明書を受け取る
1 クライアント
鍵ペアとCSRを作る
秘密鍵は手元に残し、公開鍵とCNだけをCSRで送る
→
2 発行Lambda（IAMで保護）
CSRを検証する
署名・鍵の強さ・CNを確認。SANや拡張の要求は使わない
→
3 KMS CaSigningKey
ダイジェストに署名
Sign（DIGEST / ECDSA_SHA_256）。秘密鍵はKMSの外に出ない
→
4 DynamoDB 台帳
発行を記録して返す
シリアル・CN・期限・status=ISSUED を登録
利用APIを呼び出す
1 クライアント
証明書で接続
https://api.example.com にTLS 1.2以上で接続
→
2 API Gateway
トラストストアで検証
CAのチェーン・署名・有効期間を確認
不合格ならTLS接続が失敗
→
3 Lambdaオーソライザー
台帳で失効を確認
シリアルで台帳を引き、ISSUEDかつ期限内か
REVOKED・期限切れ・未登録はDeny
→
4 バックエンド
Allowなら処理
結果はキャッシュせず、失効をすぐ反映
迂回を防ぐ既定の execute-api エンドポイントは disableExecuteApiEndpoint: true で無効化し、mTLSのカスタムドメインだけを入口にする
